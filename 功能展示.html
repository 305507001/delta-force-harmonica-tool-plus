为什么游戏里能真的响

这类工具最容易翻车的地方，这里都专门处理了

扫描码级注入

很多自动化工具用 keybd_event 或虚拟键码，游戏里完全没反应 —— 因为游戏走 RawInput/DirectInput，读的是硬件扫描码。本程序标记 KEYEVENTF_SCANCODE 直接投递扫描码，和真实键盘按下时产生的数据包一致。

帧对齐余量

游戏按渲染帧读键盘。如果鼠标修饰键和音键的按下时间差小于一帧（60FPS ≈ 16.7ms）， 游戏会读到「修饰键还没生效」那一帧，音就吹错八度甚至不响。所以所有时序参数都以帧为单位， 并且最小间隔按物理毫秒算，不随播放速度压缩。

单声部槽位排布

口琴一次只能发一个音。遇到时间重叠的音符，不能靠缩短前一个音来腾地方 （会切出零时长按键，游戏直接吞掉），而是把这个音顺延到前一个音之后， 形成互不重叠的槽位。

八度折叠

超出音域的音会整体平移若干八度落到音域内，同时保持音级关系 （比如 E7 → E5）。旋律的调性和走向不会被打乱，比直接丢掉这些音体验好得多。

修饰键差分切换

连续多个音用同一套修饰键时，只在组合真正变化时才发鼠标事件， 既不浪费注入量，也减少抖动。

零第三方依赖

只用 Python 标准库：ctypes 调 Windows API，tkinter 做界面， MIDI 解析器是自己写的（两遍法解析 + 变速时间轴）。 不需要 pip install 任何东西。
